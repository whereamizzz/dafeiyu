## 三、首次推上去

```bash
cd D:\dafeiyu
git init
git add .
git commit -m "V1.0: Windows 微信 AI 助手，群聊接话 + 判分门禁 + 单文件控制台"
git branch -M main
git remote add origin https://github.com/<你的用户名>/dafeiyu.git
git push -u origin main
```

推之前自查三条：

1. **`config.yaml` 和 `data/` 没有被提交**（`.gitignore` 已经排掉，但 `git status` 再看一眼）；
2. `git grep -n "sk-"` 搜不到真 Key；
3. `git grep -n "wxid_"` 只剩代码里的通用写法。

## 五、关于"加 star"

老实说：**能做的只有把东西做好看、说清楚**。以下几件事是真有用的：

1. **首图决定一切**。现在 README 第一屏是标题 + 一句话 + 截图，截图里能看见"判分、档位、白名单"。别把长表格放最上面。
2. **把"风险"写明白反而更容易被信任**。抢前台这件事写清楚了，评论区就少一半"这是个木马吧"。
3. **标题里带关键词**：README 顶部那句已经写了「Windows 微信机器人」，搜索能命中。
4. **别刷 star、别买 star**。GitHub 会清，而且会被社区挂。
5. 发到相关社区时（V2EX、即刻、小红书、B 站），**讲一个具体场景**比讲功能列表有用。比如"我妈的广场舞群里，它负责在没人说话的时候抛个话题"。

## 七、许可

已经用 **MIT**。理由：

- 这类工具本来就是玩具性质，MIT 最省事，别人拿去改也不会有法律负担；
- 想防止"拿去卖"的话可以换 AGPL-3.0，但会劝退一部分贡献者；
- 无论选哪个，**风险与免责声明必须留在 README 里**，这是比协议更实际的东西。
